MCN Boot is a Java application development toolkit built on Spring Boot and Spring Cloud.
It provides reusable infrastructure and convention-based auto-configuration for Servlet,
Reactive, and non-web applications.

== Features

* Conditional Spring Boot auto-configuration based on the classpath and application properties
* Support for Servlet, WebFlux, and non-web applications
* Shared JSON handling, response models, exception handling, and request parameter processing
* Extensions for JDBC, JPA, MyBatis, MongoDB, Redis, MinIO, and other common components
* Web infrastructure for CORS, validation, data integrity, and health checks
* Extensions for RestTemplate, WebClient, OpenFeign, Spring Security, and OAuth2 Resource Server
* OpenAPI documentation based on springdoc-openapi and Knife4j

Optional features are activated only when their corresponding dependencies are present.
Applications should include only the components they actually use.

== Modules

|Provides dependency and plugin management for Maven applications

|`mcn-boot-autoconfigure`
|Provides general Spring Boot auto-configuration

|`mcn-cloud-autoconfigure`
|Provides Spring Cloud, client, and security auto-configuration

|`mcn-spring-boot-starter`
|Provides the primary entry point for adding MCN Boot to an application

|`mcn-swagger3`
|Integrates springdoc-openapi and Knife4j
|===

== Getting Started

=== Requirements

* JDK 17 or later
* Maven 3.6.3 or later

=== Use the Parent POM

Create a Maven project that inherits from `mcn-boot-starter-parent`:

[source,xml,subs="attributes+"]
----
<parent>
    <groupId>cn.hiboot.mcn</groupId>
    <artifactId>mcn-boot-starter-parent</artifactId>
    <version>{project-version}</version>
</parent>
----

Add the MCN Boot starter and the Spring Boot starters required by your application:

[source,xml]
----
<dependencies>
    <dependency>
        <groupId>cn.hiboot.mcn</groupId>
        <artifactId>mcn-spring-boot-starter</artifactId>
    </dependency>

    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-webmvc</artifactId>
    </dependency>
</dependencies>
----

=== Use the BOM

If the application cannot inherit from the MCN parent POM, import `mcn-boot-dependencies` instead:

[source,xml,subs="attributes+"]
----
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>cn.hiboot.mcn</groupId>
            <artifactId>mcn-boot-dependencies</artifactId>
            <version>{project-version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

<dependencies>
    <dependency>
        <groupId>cn.hiboot.mcn</groupId>
        <artifactId>mcn-spring-boot-starter</artifactId>
    </dependency>

    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-webmvc</artifactId>
    </dependency>
</dependencies>
----

=== Create an Application

[source,java]
----
package com.example.demo;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class DemoApplication {

    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }
}
----

Set the application name in `src/main/resources/application.yml`:

[source,yaml]
----
spring:
  application:
    name: demo
----

Run the application:

[source,shell]
----
mvn spring-boot:run
----

If the current source version has not been published to a Maven repository, run `mvn install`
from the root of this project first.

== OpenAPI Documentation

Add `mcn-swagger3` when the application requires API documentation:

[source,xml]
----
<dependency>
    <groupId>cn.hiboot.mcn</groupId>
    <artifactId>mcn-swagger3</artifactId>
</dependency>
----

Enable Swagger configuration:

[source,yaml]
----
swagger:
  enabled: true
  title: ${spring.application.name} API
  version: 1.0.0
----

After starting the application, open `http://localhost:8080/doc.html`.

== Website Development

The product home page and documentation use VitePress 1.6.4 with a shared custom theme.
Install the website dependencies and start the local development server from the repository root:

[source,shell]
----
npm install
npm run docs:dev
----

The site retains its `/mcn/` base path. Follow the URL printed by the development server.
Build and preview the production output with:

[source,shell]
----
npm run docs:build
npm run docs:preview
----

The build also runs `docs:check`, which checks the pre-rendered headings, internal links,
section anchors, static resources and `/mcn/` deployment path. It does not check external sites.
The deployable output is `docs/.vitepress/dist/`; serve its contents under `/mcn/`.

`docs/.vitepress/theme/HomePage.vue` contains the product page,
`Layout.vue` adds shared reading and navigation context, and `styles.css` defines the
warm paper and terracotta appearance in light and dark modes. Documentation remains in
`docs/` as Markdown. Search, code copying, mobile navigation and the page outline use
VitePress's built-in features. The theme does not load external fonts or a search service.

The advanced tutorials import their Java and properties examples directly from `docs/examples/`.
Compile the examples and run their contract tests against the current reactor modules with:

[source,shell]
----
mvn -Pdocs-check test
----

The `docs-check` profile adds the example module only when explicitly selected; the normal
reactor excludes it. Use the `test` goal above for verification. Tests cover response
serialization, documented property binding and activation defaults, Jackson string processing,
parameter rejection rules, datasource scope cleanup, lock cleanup,
SM2 round trips and request digest construction. They do not connect to a real database,
Redis, configuration center or external servlet container. Validate those integrations in
the application's own environment before relying on their behavior.
